# Decisions

One line per decision. Later sessions read this instead of reopening settled questions.

| Date | Decision | Who decided | Why |
|---|---|---|---|
| 2026-10-25 | Ship as a Claude Code plugin marketplace plus a multi-framework kit | Yen-Ching Wu | One-command install for Claude Code users, same discipline for other frameworks |
| 2026-10-25 | Build on Learn Harness Engineering's ideas with credit, no copied files | Yen-Ching Wu | Recycle the best approach; add safety, evals and cost areas the course leaves out |
| 2026-10-26 | Extend the kit with four tracks supported (full) — LangGraph, OpenAI Agents SDK, CrewAI, AWS Strands Agents — and assess-only tracks for the next most used frameworks | Yen-Ching Wu | Cover the frameworks buyers' teams already use without diluting "proof, not words": full only where the kit ships a real trace hook and smoke test |
| 2026-10-26 | Add Vercel AI SDK as an eighth assess-only track; no separate tracks for AutoGen or Semantic Kernel (Microsoft Agent Framework succeeds them) | Cowork, for owner review | Vercel AI SDK is current and widely used in TypeScript; separate AutoGen/SK tracks would duplicate MAF |
| 2026-10-26 | Every track describes itself in harness_track.json (harness-track/1) | Cowork, for owner review | One shape that the kit, its tests and assessors such as OpenProof can read without per-framework code |
| 2026-10-26 | Guard checks G1-G3 judge each framework by its own mechanism (explicit tool list, approval or deny gate); declared evidence for assess-only tracks earns half weight; a check passes only when every agent surface passes | Yen-Ching Wu (approved the fix) | A narrow non-Claude harness lost up to 8 of 100 points for not using .claude/settings.json; the same guard quality must earn the same points |
| 2026-10-27 | Guard credit requires attachment to the scored agent and tool; what the audit cannot read is UNRESOLVED, never VERIFIED or MISSING; inline refusals earn the same as framework hooks | Cowork, for owner review (Codex round-1 findings R1-01 to R1-04) | The same guard quality must earn the same points in both directions: no credit for unattached guards, no penalty for equivalent inline ones |
| 2026-10-27 | Live presets run the production work agent (`--task`); a run that did not complete is UNRESOLVED; `harness verify` treats files changed during the run as not clean evidence | Cowork, for owner review (Codex round-1 findings R1-05, R1-06, R1-08) | A red-team or verification result is only proof about the agent and tree that actually shipped |
| 2026-10-27 | Credit only what is proven: a guard counts when it is explicit, unconditional and attached to the scored agent or tool; narrower, conditional or unprovable guards are UNRESOLVED with a named reason; a capability the audit cannot rule out is reported, never assumed absent | Coordinator brief for 1.4.3, for owner review (Codex round-2 findings R2-01 to R2-05) | Round 2 found credit for guards that do not hold on every input; UNRESOLVED keeps the score honest without guessing |
| 2026-10-27 | CrewAI `Task(human_input=True)` earns no G1-G3 credit | Builder, for owner review (R2-02) | It reviews the task's final answer after tools have run, so it approves no tool call |

| 2026-10-27 | Tests never read older commits; base versions are vendored and pinned by blob id and sha256 | Builder (CI defect on preview-1.4.2) | GitHub checks out shallow clones and downloads have no `.git` |
| 2026-10-27 | Credit only canonical guard forms: a code refusal earns points only in the written list F1-F7 (`CANONICAL_FORMS` in audit.py, `--canonical-forms`, the audit's SKILL.md); every other shape is UNRESOLVED with a named reason, even when it is correct | Coordinator brief for 1.4.4, for owner review (Codex round-3 findings R3-01, R3-02) | Rounds 1-3 each closed the reported shapes and the reviewer found neighbouring ones; proving arbitrary Python control flow keeps losing, a short written list does not |
| 2026-10-27 | The kit ships one guard helper, `kit/shared/kit_guard.py`; the audit trusts `kit_guard.refuses` only while its sha256 matches the pinned hash | Builder, for owner review (brief: "the kit's own shipped guard helper identified by module path and pinned content hash") | Gives teams a canonical way to earn credit for a real check without the audit reading arbitrary helper code |
| 2026-10-27 | Reach fails closed: every call a tool makes is followed whatever its arguments; unknown targets are UNRESOLVED; deletes and destructive fixed commands are irreversible by operation | Coordinator brief for 1.4.4 (R3-03) | Absence of a capability must be proven, never assumed from argument flow |
| 2026-10-27 | Agent SDK `disallowed_tools` and Claude Code settings share one rule-scope function; a destructive rule needs a wildcard to cover the class | Coordinator brief for 1.4.4 (R3-05) | The same rule must earn the same credit from either source |
| 2026-10-27 | Sandbox: Read deny rules bind Bash only with `allowUnsandboxedCommands: false` and no `excludedCommands`; a whole-Bash ask is not credited while `autoAllowBashIfSandboxed` is on (both default on); the templates set `allowUnsandboxedCommands: false` | Builder, for owner review (R3-06) | Claude Code's sandbox docs: excluded and unsandboxed commands run outside the filesystem boundary, and auto-allow skips bare Bash asks for sandboxed commands |
| 2026-10-27 | The repo's own `.claude/settings.json` is left unchanged in 1.4.4 (it lacks `allowUnsandboxedCommands: false`, so self-audit G2 is UNRESOLVED, score 93) | Builder; the file is write-protected in the builder's session, change is the owner's | Changing this repo's own permission settings is an owner decision |
| 2026-10-27 | Before a review package goes out, an independent agent tries to break the canonical list; its bypasses are closed and kept as fixtures (`tests/fixtures/review_1_4_4/`) | Builder | The builder's own tests found 4 holes and the independent pass found 13 more; cheaper than another Codex round |
| 2026-10-27 | A guard earns nothing in a module that any repo file changes at run time (globals(), setattr, attribute stores on its names) or under a non-framework decorator | Builder, for owner review | Static reading cannot see the function that actually runs once names are replaced; failing closed is the canonical-forms rule |
| 2026-10-27 | Code refusals earn credit only through the kit helper (`from kit_guard import refuses`, first statement, the parameter passed straight as the capability's operation argument) or a framework's exact documented contract; hand-written refusals are UNRESOLVED "hand-written refusal: use the kit guard helper to earn credit" | Coordinator brief for 1.4.5, for owner review (Codex round-4 findings R4-01 to R4-07) | Four rounds of proving arbitrary Python each found neighbouring shapes; a shape the audit can check completely gives predictable results. Teams lose credit for correct hand-written guards and earn it back with the helper |
| 2026-10-27 | The helper defines the classes: a credited refusal covers secret and destructive as kit_guard.py documents them; F7's keyword rule is removed | Coordinator brief for 1.4.5 (R4-07, R4-08) | One keyword never proved a class; the helper is tested over a generated class table instead |
| 2026-10-27 | The Agent SDK hook may give the helper one field (`command` for Bash, `file_path` for Read/Write/Edit/MultiEdit) only inside a scope naming those tools; elsewhere the whole `tool_input` | Builder, for owner review | The whole input of Write includes the file content, so a whole-input check would refuse ordinary writes that mention `git push`; the field is what the built-in tool executes |
| 2026-10-27 | For a file-write tool the helper's classes are credited as for any tool, although it does not limit where a tool writes | Builder, for owner review (the brief: "a helper-guarded tool gets the classes the helper covers") | Restricting writes to the repo would need a path class the helper does not have; recorded as a residual, not proven |
| 2026-10-27 | The fairness matrix uses helper forms of the four hand-written round-1 `c` fixtures (`tests/fixtures/fairness_1_4_5/`); the originals are asserted UNRESOLVED | Builder, for owner review | The matrix measures "same guard behaviour, same points"; the originals' change is the mechanism rule, not a track preference |
| 2026-10-27 | `can_use_tool` decides instead of a person: it earns credit only in its contract form, and one that may return `updated_input` voids every hook refusal on the agent | Builder, for owner review (found while extending R4-06) | A callback is not a person; a rewritten input is not the one the hooks checked |
| 2026-10-27 | `sandbox.filesystem.disabled` (or an unreadable `sandbox.filesystem`) voids the Read-deny binding for Bash; `failIfUnavailable` is not yet required | Coordinator brief for 1.4.5 (R4-09); builder for the second half | Docs say disabling filesystem isolation keeps only network isolation. Whether commands run unsandboxed when the sandbox cannot start is not established offline here: UNRESOLVED |
| 2026-10-28 | An independent reviewer that declines to build bypasses still names seams; each named seam is closed with red tests before packaging | Builder | Two reviewer agents stopped (one on a classifier, one by its own judgment); the named seams were concrete enough to test |
| 2026-10-28 | The live red team's trace is written by its own first hook, before any refusal; a refusal that hides an attempt from the trace is a defect | Coordinator brief 1.4.5b | Detectors judge what the agent attempted; 1.4.5 put the canonical refusal ahead of the trace write and the planted-file test lost its evidence |
| 2026-10-28 | The helper reads a glob as a superset (a bracket is any one character, `?` one, `*` any run, a leading dot included) and refuses a part that can match a secret name; with the open secret families this refuses every part holding a `*`, including the brief's `*.py` and `src/*.json` examples | Builder, for owner review (brief 1.4.6, R5-01) | `*.py` can match `.env_x.py`, `credentials.py` and `a.key.py`, and `src/*.json` can match `src/credentials.json`, all documented secret names; allowing them needs a narrower class (closed suffix lists) or the shell's leading-dot rule, which `find -name` does not follow. Owner decides whether to narrow the class |
| 2026-10-28 | kit_guard imports nothing; the audit voids helper credit when a standard-library-named module or package sits in a folder that may lead sys.path for the guard or the helper (the root and every folder down to each), or when a repo file patches any standard-library module | Coordinator brief for 1.4.6 (R5-03) | A file in the repo could replace a module the helper or the capability loads, so the pinned bytes no longer fix the behaviour |
| 2026-10-28 | F2 binds positional and keyword arguments to each capability's real signature; credit only when P is the sole operation-bearing argument and every other argument is a literal on the written allow-list | Coordinator brief for 1.4.6 (R5-02) | Positional `executable` and `env` changed what runs while P looked harmless |
| 2026-10-28 | Every Claude Agent SDK PreToolUse hook on an agent may return only `{}`, None or the deny literal; anything else voids every hook's credit on the agent, whatever the order | Coordinator brief for 1.4.6 (R5-04); None added by the builder (it carries no output) | An `updatedInput` from a named value or helper replaced the input after the guard passed it; SDK hooks may run in parallel |
| 2026-10-28 | The helper joins backslash-newline line continuations as the shell does before any other step, and fails closed: it also removes every pair wherever it is and refuses when any form, the unjoined one included, is refused | Coordinator brief for 1.4.7 (R6-01) | `_tokens` turned newlines into separators before handling backslashes, so a continuation split a secret name or a program name the shell then joined |
| 2026-10-28 | A module may only be read and called anywhere in the tree the audit reads; binding one to another name, handing one on, storing through something that is or may be a module, sys.modules, importlib, `__import__`, namespaces and frames withhold all helper credit in the tree, UNRESOLVED with file and line | Coordinator brief for 1.4.7 (R6-02); the handing-on, namespace and frame rules and the list of outside callables that may hand a module on are the builder's, for owner review | A second ordinary assignment of a module handle carried a patch the old resolver did not follow; failing closed on every binding form ends that family. | 2026-10-28 | Parameters count as not-a-module for attribute stores (a hook's event, a method's self); repo code may not hand a module to a function | Builder, for owner review | Treating every parameter as may-be-a-module would void every Strands cancel and MAF result refusal; the call-site rule keeps modules out of parameters the repo controls, and a framework's arguments are taken to be its documented objects |
| 2026-10-28 | A name imported with `from` from outside the repo counts as a module unless it is capitalised (taken to be a class) | Builder, for owner review | The audit never imports the code it reads, so it cannot tell a submodule from a function; capitalised names are classes by convention and are passed to registries (`add_callback(BeforeToolCallEvent, ...)`). Residual: a capitalised module (`ElementTree`) passed on |
| 2026-10-28 | `sys.path.insert(0, <this file's folder>)` is allowed; every other change to sys.path is a module change | Builder, for owner review | The Agent SDK starter adds its own folder so `kit_guard` imports from any working directory; that folder is one the standard-library shadow check already reads |
| 2026-10-28 | F5 models only plain and annotated assignment of the SDK options; every other binding form is UNRESOLVED, and any `.options` attribute in the tree voids the hooks | Coordinator brief for 1.4.7 (R6-03); `.options` by the builder | An annotated binding skipped the later-use checks; a client keeps its options on `.options` until it connects |
| 2026-10-28 | Each fetch callable has its own option list from its signature; a fetch callable outside the table earns nothing (a named client, aiohttp, urllib3, http.client) | Coordinator brief for 1.4.7 (R6-04); the table's extent is the builder's | One shared list gave credit to `urlopen(url, headers=...)`, which raises TypeError; a narrower table keeps credit predictable |
| 2026-10-28 | The helper refuses a word with more than four brace groups or more than 64 brace expansions, and expands brace sequences | Builder, for owner review (independent review of 1.4.7) | A limit that silently dropped expansions let `x{1,2}...{1,2}/.{e,x}nv` through; failing closed is the helper's rule |
| 2026-10-28 | Options returned from a function count only when every use of the function is a call passed whole to the SDK | Builder, for owner review (independent review of 1.4.7) | F5 allowed "returned", and a caller could clear the hooks of the returned options |
| 2026-10-28 | Files under tests/ or vendor/ that nothing imports stay outside F5's other-file rule, as for F1's tree rules | Builder, for owner review | They run only under a test runner or not at all; the scope was settled in 1.4.5 (67ca076) |
| 2026-10-28 | A module value may only be used as `m.attr`, `m.attr(...)`, an item read, iteration through an attribute, or a test or comparison; any other use, getattr/hasattr on it included, withholds all helper credit in the tree | Coordinator brief for 1.4.8 (R7-01); hasattr, keys and the outside-attribute exception by the builder | getattr let a module reach a repo function that replaced a capability; a closed list of allowed uses replaces a list of forbidden ones |
| 2026-10-28 | An outside module's attribute (`subprocess.PIPE`) may still be passed to an outside callable not on the hand-on list in the same expression, or be in an isinstance/except tuple; a module name may not be passed even to print | Builder, for owner review | Ordinary calls such as `subprocess.run(c, stdout=subprocess.PIPE)` and `isinstance(e, (socket.timeout, ssl.SSLError))` would otherwise lose all credit; the residual is the existing one (an outside callable not on the list that hands its argument on) |
| 2026-10-28 | SDK options earn credit only when bound at module level or as a function local; class namespaces, instance attributes, defaults, containers and class-defined returning functions are UNRESOLVED | Coordinator brief for 1.4.8 (R7-02); returning methods by the builder | The later-use scan sees names, not class attributes; a method's callers reach it through attributes the scan cannot follow |
| 2026-10-28 | Each capability's options are its own list, and each value must be one the real callable takes alone and with the other written options; a test calls every credited single option and pair for real | Coordinator brief for 1.4.8 (R7-03); the value rules by the builder | check_output raised for check and capture_output; the differential test also found codecs.open(buffering=0) and text with universal_newlines |
