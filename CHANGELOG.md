## 1.4.8 (28 Oct 2026)
Fix round for Codex's round-7 review of 1.4.7 (2 P1, 2 P2, one boundary observation). Each finding first got a failing test from the reviewer's fixtures (`tests/fixtures/codex_r7/`, `tests/test_audit_r7.py`) and a generated family (1308 failing cases on 855ccb5, `deliver/1.4.8/logs/red_r7_vs_855ccb5.log`).
- **Module values (F1, R7-01).** F1 now states the only allowed uses of a value that is or may be a module: an attribute read or call (`m.attr`, `m.attr(...)`), an item read, iteration through an attribute, a test or comparison (and, for an outside module's attribute, an argument to an outside callable not on the hand-on list, or a class in isinstance/except tuples). Every other use withholds helper credit tree-wide, with the file and line: binding in any form, passing as an argument (a module name even to print), returning or yielding, a container or a subscript key, a class or instance attribute or default, and being the target of getattr, hasattr, setattr, delattr, vars or `__dict__`. `getattr(<module value>, ...)` is itself a violation, so its result can no longer be handed on.
- **Where the SDK options are bound (F5, R7-02).** Credited options are bound once at module level or as a function local by a plain or annotated assignment. A class namespace (nested classes and classes inside functions included), an instance attribute, a default, a container, or options returned by a function defined in a class namespace are UNRESOLVED.
- **Each callable's own options (F2, R7-03).** `check_output` no longer takes `check` or `capture_output` (it raises for both). Each written option's value must be one the real callable accepts, alone and with the other written options: booleans for flags, a positive number or None for timeout, a codec Python knows, a standard error handler, a valid mode per callable (os.popen r or w, codecs.open no t), buffering 0 only for a binary `open()`, a valid newline, no encoding/errors/newline in binary mode, never both text and universal_newlines. A test calls every credited single option and pair for real on `true` and scratch files.
- **Capitalised classes (F1, R7-04).** A name imported with `from` from outside the repo whose imported and bound names are both capitalised is a class everywhere: it may be bound, passed to repo functions and held in containers (a store on it still counts). A lower-case module renamed capitalised (`from os import path as Path`) is still a module value. The residual (a capitalised outside module such as ElementTree) is stated in F1.
- **Braces in destructive commands (kit_guard version 5).** Brace groups are expanded before the destructive check: a command is refused when a word read as any one of its expansions, or as all of them in a row as the shell does (`{git,push}`), gives a destructive command. More than four braced words in one command, a group past the existing limits, or more than 256 readings is refused.
- **Independent review before packaging (`tests/test_audit_review_1_4_8.py`, `tests/fixtures/review_1_4_8/`).** A first conformance reviewer stopped part way (F1 only) and found modules that run code strings or files (timeit, runpy, cProfile, profile, pdb, code, pickle) and a mutating method through an outside call's result (`pkgutil.resolve_name('sys').path.insert`); 10 cases failed at 5397389. A second reviewer covered F2, F5 and the helper and found 33 failing cases at 0b2933f: credited values the real callable rejects (non-text codecs, huge buffering or timeout, tiny timeouts, empty or NUL cwd, a codec name that crashed the audit), a working `codecs.open(..., 0)` refused, a decorator on the options function and `match` class patterns reading `options`, and helper misses (quoted or escaped braces inside a group, quoted spaces in an alternative given to `bash -c` or `eval`, `env -S`). All closed. Reported and not changed: quoted words holding a documented member (`git commit -m 'no rm -rf'`) stay refused, as the docstring's "wherever the program appears" says.

- **Line continuations (kit_guard version 4, R6-01).** Before any other step, every string (and every item of an argument vector) is also read with each backslash-newline pair removed the way the shell removes a line continuation (outside single quotes, inside double quotes too), and with every pair removed wherever it is. The value is refused when any form, the unjoined one included, is refused; a nested shell (`bash -c '...'`) joins its own lines at each level. `cat .en\<newline>v`, `git pu\<newline>sh` and `rm --recur\<newline>sive x` are refused. New table: every documented secret and destructive member split at every position, unquoted and double-quoted, two continuations at every pair of positions, a `/bin/sh` differential (printf in front, nothing executed) and ordinary continued commands that stay allowed. New pinned sha256 `2c56e596...` (after the review round below); copies synced.
- **Module objects (F1, R6-02).** In any file the audit reads, a module may only be read (`m.attr`, `m[...]`) and called. Binding one to another name in any form, returning or yielding it, putting it in a display, passing it to a repo function, an unresolved method or an outside callable that may hand it on, storing an attribute on (or setattr/delattr of) something that is or may be a module (a base the audit cannot resolve counts as may-be), mutating an object a module holds, any importlib, imp, gc, ctypes, inspect or unittest.mock import, `sys.modules` and the other import and frame hooks, `__import__`, `globals()`, namespace and frame attributes, and getattr with a computed name withhold credit from every helper-credited tool and hook in the tree, UNRESOLVED with the file and line. `os.environ` and `sys.path.insert(0, <this file's folder>)` (a folder the shadow check reads) are not module changes. A helper whose credit is withheld is no longer walked as a capability, so the guard reads UNRESOLVED with the reason instead of MISSING.
- **Every binding form of the SDK options (F5, R6-03).** The options are passed whole to the SDK, returned, or bound to one name by a plain or annotated assignment; any other binding form is UNRESOLVED. Every binding form counts as a second binding (augmented and annotated assignment, a bare annotation, walrus, for, with, except, match, import, global, nonlocal, del, def, class, comprehension). Another file importing the name or reading it through the module, and any `.options` attribute (a client keeps its options there until it connects), void the hooks too.
- **Per-callable fetch options (F2, R6-04).** Each fetch callable has its own options from its signature: requests (functions and an inline `Session()`): timeout, headers, allow_redirects, verify; httpx functions: timeout, headers, follow_redirects, verify; an inline `httpx.Client()`'s methods: no verify; `urlopen`: timeout; `Request`: headers and a literal method; `urlretrieve`: nothing; `request`/`stream`: also a literal method. A fetch outside the table (a named client, aiohttp, urllib3, http.client) earns nothing. The standard-library rows are checked against `inspect.signature`; requests 2.32 and httpx 0.28 are taken from their documented signatures (neither is installed here).

Over-refusals fixed: an item read of a module attribute (`sys.argv[0]`), a loop over one (`for p in sys.path`) and `sys.path.insert(0, HERE)` with HERE bound once to this file's folder. Not changed, recorded: an unimported file under tests/ or vendor/ that changes the options (same scope as F1's tree rules), a hooks dict held in a name (already unreadable, now said in F5's examples' sense), and words such as `echo git push` that the helper refuses by design ("wherever the program appears").

## 1.4.6 (28 Oct 2026)
Fix round for Codex's round-5 review of 1.4.5b (4 P1). Each finding first got a failing test from the reviewer's fixtures (`tests/fixtures/codex_r5/`, `tests/test_audit_r5.py`) and a generated family (4014 failing cases on 81877ed).
- **Globs are over-approximated (kit_guard version 3, R5-01).** A path part holding `*`, `?` or `[` is read as a superset of what the shell could expand it to (a bracket expression is any one character, `?` one character, `*` any run, a leading dot included) and refused when that superset can match a secret name. The secret families are open (`<any>.key-<any>`, `.env<any>`, `credentials.<any>`), so every part with a `*` can match one and is refused: `cat id_d*`, `cat *dsa`, but also `ls *.py`, `src/*.json` and `pytest tests/*`. `?` and brackets are refused only where a secret name fits (`id_?sa` yes, `README.m?` no). A glob part over 256 characters is refused. New table: every glob spelling (`?`, `[c]`, `[!#]`, every `*` prefix, suffix and middle) of every documented secret name, in four input shapes (about 15,000 cases), plus controls.
- **The helper imports nothing (R5-03).** It has its own POSIX-style tokenizer, %-decoding and brace expansion, so no repository file can replace a module it uses (differential check: the same tokens as `shlex` on 60,000 fuzzed strings). The audit also voids helper credit when a module or package named like a standard-library module sits in a folder Python may put first on `sys.path` for the guard module or the helper (the root and every folder down to each), or when any repo file patches a standard-library module. New pinned sha256 `949cb6e9...`; copies synced.
- **F2 binds arguments to the real signature (R5-02).** Positional and keyword arguments are bound to the capability's signature (Popen's positional order for `subprocess.*`, `open`'s, each fetch method's). P must be the only operation-bearing argument; every other argument must be a literal on the written list (`shell`, `capture_output`, `text`, `check`, `timeout`, `encoding`, `errors`, `universal_newlines`, an in-repo relative `cwd`; `mode`, `buffering`, `encoding`, `errors`, `newline` for open; `timeout`, `headers`, redirects, `verify`, a literal method for a fetch). `subprocess.Popen(command, -1, '/x/runner')` and an environment passed positionally now earn nothing.
- **Other SDK hooks must provably return nothing (R5-04).** Every PreToolUse hook on an Agent SDK agent, the credited one included, may return only `{}`, None or the F3 deny literal. A named value, computed key, `**` unpacking, helper return or imported value voids the guard credit of the whole agent, whatever the registration order (the SDK may run matching hooks in parallel). The Agent SDK starter's `deny_secrets` now returns the deny literal directly; it keeps 8/8.
- **Generated near-misses (`R5NearMisses`):** positional options per capability signature, keyword options outside the list, standard-library shadows beside the guard and at the root, and 18 other-hook outputs in both registration orders and in a second matcher.
- **Independent review before packaging (`tests/test_audit_review_1_4_6.py`, `tests/fixtures/review_1_4_6/`).** A spec-conformance reviewer agent found 24 inputs that earned credit the written forms do not allow and 7 helper misses (43 failing cases at c9ad575). Closed: tampering through `vars(x)`, `__setattr__`/`__setitem__` calls, `operator.setitem`, exec/eval/compile, or a name bound to a module, its `__dict__` or `sys.modules`; patches in skipped folders (vendor/, build/) that a module imports; startup hooks as a package or compiled file; an unchecked-hash kit_guard pyc; `importlib.import_module('kit_guard')`; SDK hooks dicts with `**`, computed or repeated keys; options changed after they are built (`opts.hooks[...].append`, `dataclasses.replace`); a yielding hook; options a capability does not take (`os.system(c, shell=True)`); a `~` inside cwd; a callee module imported twice; `.config/./gcloud` and `%252e`. An `os.environ[...]` store is not a module change.

## 1.4.5 (27 Oct 2026)
Fix round for Codex's round-4 review of 1.4.4 (9 P1). Each finding first got a failing test, using the reviewer's fixtures (`tests/fixtures/codex_r4/`; 23 failures on 1.4.4). The rule for this round: **narrower credit, predictable results**. Four rounds of static proof over arbitrary Python each closed the reported shapes and the reviewer found neighbours, so code refusals now earn credit only through the kit's own guard helper in one exact call shape, or a framework's exact documented contract.
- **The helper is the only code predicate (harness-audit 1.4.5, F1-F2, R4-01, R4-02).** `from kit_guard import refuses` at module level, never rebound, shadowed or imported again in the module; `if refuses(P): return <literal>` (or `raise` a built-in exception) as the tool's first statement; every other use of P is the operation-bearing argument of a capability call (the command of a shell call, the file of `open()`, the URL of a fetch). P used as stdin, cwd or env, wrapped, aliased, passed to your own helper or logged earns nothing. A module changed through `sys.modules` or a computed store anywhere in the repo counts as tampered.
- **Framework contracts (F3-F5, R4-03 to R4-06).** Each hook earns credit only in its documented contract, written in CANONICAL_FORMS with a link to the framework's docs: ADK `return {<literal>}`, CrewAI `return False`, Strands `event.cancel_tool = '<literal>'` on the hook's own event, MAF `return`/`raise`/`context.result = <literal>`, Agent SDK PreToolUse the exact `hookSpecificOutput` deny literal (with `hookEventName: 'PreToolUse'`) returned directly, Agent SDK `can_use_tool` `PermissionResultDeny(message=...)`, OpenAI tool input guardrail `reject_content`/`raise_exception`. Refusals come first in the hook; a tool-scope branch starts with its refusal. The credited hook and every other hook on the same agent must leave the input alone (no alias, mutation, `updatedInput`, `updated_input`; for Strands, nothing in the repo may reset `cancel_tool`; for CrewAI, no hook registered elsewhere). `can_use_tool` is read now: it decides instead of a person, so it no longer earns "a person approves".
- **Classes come from the helper (F6, F7, R4-07).** The keyword/probe rule is gone. A credited refusal covers the helper's two classes, secret and destructive, for the calls it binds. Every hand-written refusal (an `in` test, a regex, your own predicate) is UNRESOLVED: "hand-written refusal: use the kit guard helper to earn credit".
- **The helper refuses its whole documented class (R4-08).** `kit/shared/kit_guard.py` version 2: `.env` with any suffix (`.env_x`, `.envrc`), keys with suffixes, credential folders, globs and braces that can match them, %-escapes; git push/clean and reset --hard with options in any order and git options first, abbreviated long options, rm with a recursive option anywhere, wrappers (sudo, env, xargs, bash -c), `$(...)` and backticks, argument vectors. What it does not decode is written in its docstring. `tests/test_kit_guard.py` checks a generated table of about 28,000 cases plus ordinary inputs it must let through. The pinned hash and the Agent SDK copy are updated.
- **Filesystem isolation (R4-09).** With `sandbox.filesystem.disabled` (or an unreadable `sandbox.filesystem`) Read deny rules no longer bind Bash; G2 is UNRESOLVED unless another credited guard covers it.
- **Generated near-misses:** `Round4NearMisses` (133 subtests): helper names rebound or patched, the parameter used as another argument, exits inside scope branches, contract-shape near-misses per framework, input changed by the hook or another hook, `can_use_tool`.
- **Independent review before packaging:** a separate reviewer agent declined to build working bypasses and named four seams in the checker instead; each became a red test (23 failures, `tests/test_audit_review_1_4_5.py`) and is closed: the hashed helper must be the module Python imports (no kit_guard package, compiled module or differing copy in the tree); tampering through `__dict__`/`sys.modules` methods and `importlib.reload` counts; a capability binds a refusal only when its module is not patched, its callee alias is bound once and its other options are literal and harmless (no `executable=`, `env=`, `preexec_fn=`, `input=`, `opener=`); test-named files that production code imports are scanned for tampering, kit_guard copies in test folders are ignored (they are not import roots), and `sitecustomize.py`, `usercustomize.py` or a `.pth` file anywhere voids helper credit.
- **Starters:** the Agent SDK starter splits its hook into `guard_tool_input` (helper, contract form, scoped by tool) and `deny_secrets` (finer checks on a deep copy); it keeps 8/8. The other full-track starters have no code guard to change (narrow tool surfaces) and keep 8/8.
- **False negatives by design:** every hand-written refusal now scores UNRESOLVED (0 points), including Codex's round-1 `inline_real_guard` and the `c` fixtures for the Agent SDK, ADK, CrewAI and Strands. The fairness matrix (a=8, b=0, c=2 on all 8 full tracks) is kept with helper forms of those four `c` fixtures (`tests/fixtures/fairness_1_4_5/`); the originals are asserted UNRESOLVED.

New port-free tests run the starter's hooks in order on the planted input (`DenySecrets.test_the_trace_records_a_refused_attempt`, `test_the_trace_hook_runs_first_and_never_refuses_or_changes_the_input`).

## 1.4.4 (27 Oct 2026)
Fix round for Codex's round-3 review of 1.4.3 (7 P1). Each finding first got a failing test, using the reviewer's fixtures (`tests/fixtures/codex_r3/`). The rule for this round: **credit only canonical guard forms**. Rounds 1 to 3 each closed the reported shapes and the reviewer found neighbouring ones, so the audit stops trying to prove arbitrary Python control flow.
- **Canonical guard forms (harness-audit 1.4.4, R3-01, R3-02).** A code refusal, in a tool or in a framework hook, earns credit only in the written forms F1 to F7: a top-level `if <tests>: <refuse>` before the capability; tests joined only by `or` (`in`, `not in`, `==`, `startswith`, `re.search`/`match`/`fullmatch` on a literal, a compiled module constant, `any(x in V for x in <literals>)`, or the kit's helper `kit_guard.refuses`); the tested value is the tool's own parameter, never rebound or changed, passed as is to the capability (or the hook's whole input as text, or an Agent SDK field the tool executes); class coverage is decided by fixed probes, so an anchored regex or `re.match` covers nothing. Everything else is UNRESOLVED with the reason. The list lives in one place: `CANONICAL_FORMS` in `audit.py`, printed by `audit.py --canonical-forms`, and copied into the audit's SKILL.md (a test keeps them equal).
- **The kit's guard helper:** `kit/shared/kit_guard.py` (`refuses(value)`: secret paths and destructive commands anywhere in a string or a whole tool input). The audit credits it only while its sha256 matches the pinned hash. The Agent SDK starter copies it (synced) and leads its PreToolUse hook with canonical refusals; it keeps 8/8.
- **Reach fails closed (R3-03):** every call in a tool is followed, whether or not it receives the tool's input, so a fixed `git push` moved into a zero-argument helper still needs a gate. External or unknown targets and objects are UNRESOLVED. Capabilities are recognised by operation: `Path('.env').read_text()` is a read; `shutil.rmtree`, `os.remove`, `Path.unlink`, `rm`, `git push`, `reset --hard` are irreversible whatever their target.
- **Unreadable configuration is never "no tools" (R3-04):** an imported or unreadable `mcp_servers` map, an unreadable server, or a server-wide approval (`mcp__prod__*`) of a server the audit cannot list makes the agent UNRESOLVED.
- **One rule standard (R3-05):** Agent SDK `disallowed_tools` use exactly the Claude Code settings standard; a scoped rule covers only its scope. A destructive rule without a wildcard (`Bash(git push)`) matches only the bare command and no longer covers the class.
- **Sandbox credit only without escapes (R3-06):** Read deny rules count for Bash only when the sandbox is on with `allowUnsandboxedCommands: false` and no `excludedCommands`; a whole-Bash ask counts only with `autoAllowBashIfSandboxed: false` (both settings are on by default). The init template and the Claude Code track now set `allowUnsandboxedCommands: false`.
- **Every read is contained (R3-07):** the real path of every file the audit reads must be inside the audited root, so a `.claude` folder linked out of the repo is not read.
- **Generated near-misses:** `tests/test_audit_nearmiss.py` adds the round-3 families (for/while/with, loop-local exits, wrong parameter or field, rebinding and in-place changes, readable helpers, anchored regexes, hook exits of any shape, undone Strands cancels, SDK returns that only mention deny, serialised input, zero-input helpers, unknown MCP maps, directory and file links). On 1.4.3 the new tests fail 262 subtests (and 3 tests error: the canonical-forms list and helper pin do not exist there).
- **Independent review before packaging:** a separate reviewer built 13 shapes that matched the list's spelling but did not stop the call (a redefined `any`/`str`/`re`, constants or `kit_guard.refuses` replaced at run time, a repo decorator, an aliased `call_next`, `setattr` undoing a Strands cancel, an SDK dict whose repeated key reads as allow, forged tool names such as `ctx.agent.name`, and `requests.Session().get(url)`). All are closed and red-tested (`tests/fixtures/review_1_4_4/`): trusted names must be the real ones, a repo-wide scan withholds credit from modules changed at run time, only framework decorators are allowed, and tool names and inputs are the frameworks' exact fields.
- **False negatives by design:** correct guards in other shapes now score UNRESOLVED (0 points) with the reason, for example an allow-list, a refusal nested under an always-true constant, a check on `command.strip()`, a list-wrapped command (`['sh', '-c', command]`), a hook that returns early for other tools, or a helper predicate of your own. Rewrite them in a canonical form, or call `kit_guard.refuses`.
- Unchanged: the eight-track fairness matrix (a=8, b=0, c=2 on every track), the kit starters (8/8 on every full track), assess-only declarations (4/8). harness-init 1.4.4 (template sandbox setting); other plugins unchanged.

## 1.4.3 (27 Oct 2026)
Fix round for Codex's round-2 review of 1.4.2 (6 P1). Each finding first got a failing test, using the reviewer's fixtures (`tests/fixtures/codex_r2/`). The rule for this round: **credit only what is proven**.
- **Refusals must hold on every path (harness-audit 1.4.3, R2-01).** A refusing condition is split into its OR-branches; a branch covers secrets or destructive commands only when every part of it tests the tool's input for that class. A refusal nested under a flag or another tool's name, behind an earlier pass-through exit, inside `try`/`while`/`match`, inverted (`not ...`, `not in`, `is False`) or matching exact values only is UNRESOLVED with the reason, never VERIFIED. An AND of two classes covers neither, including one hidden inside `any(...)`; `all(...)` and filtered `any(... if ...)` are conditions too. Combining hook conditions keeps each one's restrictions.
- **CrewAI `Task(human_input=True)` is not a per-call approval (R2-02):** a person reviews the task's final answer after the tools have run. It earns no G1-G3 credit and is never credited to another agent.
- **Reach never drops a capability silently (R2-03):** local and module aliases (`runner = subprocess`), `Path(p).open()`, and fixed commands are followed. A fixed `git push` is an irreversible action that needs a gate; a fixed `git status` is listed in the evidence. Computed calls (`getattr(...)(...)`) and methods on objects the audit cannot follow are UNRESOLVED.
- **Agent SDK MCP tools bind to their server (R2-04):** the implementation is the one passed to `create_sdk_mcp_server(tools=[...])` for that key of `mcp_servers`, whatever the declaration order; unreadable or external servers are UNRESOLVED. Any `allowed_tools` rule for a tool (for example `Bash(*)`) auto-approves it.
- **Claude Code rules keep their scope (R2-05):** a scoped `ask` or `deny` rule covers only its scope (`Bash(git status *)` gates nothing else; `Bash(git push origin main)` is narrower than `Bash(git push *)`; `Read(./config/.env)` is narrower than `Read(./**/.env)`). `ask` outranks `allow`. With the sandbox enabled, Read deny rules also bind Bash. A settings file the audit cannot read makes the checks UNRESOLVED.
- **The audit reads only the repo:** it never opens secret-looking files and never follows a symlink out of the audited tree; a guard or setting that lives behind such a link earns nothing.
- **Agent SDK starter: links are checked, not names (R2-06).** `search_code` resolves every file before opening it and skips targets that are secret or outside the repo (`ordinary.txt -> .env` no longer leaks); links that stay inside the repo to ordinary files still work. The PreToolUse hook refuses file tools through such links.
- **CI:** the base-comparison test no longer calls `git show 24bc1da:...` (which fails in GitHub's shallow checkout and in downloads without `.git`); 1.4.1's `audit.py` is vendored under `tests/fixtures/audit_1_4_1/`, pinned by git blob id and sha256, and a mismatch fails.
- **Generated near-miss tests (`tests/test_audit_nearmiss.py`):** for every guard kind the audit credits, a positive earns full credit and one-change variants earn none (narrower scope, another agent, another MCP server or implementation, a condition, a symlink, a Boolean that reads true but means false, an `and` hidden inside `any(...)`). 137 generated cases; 96 fail on 1.4.2.
- Unchanged: the eight-track fairness matrix (a=8, b=0, c=2 on every track), the kit starters (8/8 on every full track), assess-only declarations (4/8). Other plugins stay at 1.4.2.
